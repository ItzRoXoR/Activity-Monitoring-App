# Приложение для мониторинга активности

Мобильное приложение для отслеживания физической активности: шаги, тренировки, калории, вес. Пользователь регистрируется, заполняет профиль, выбирает тренировки из каталога, проходит их с таймером и видит свою статистику по целям.

## Архитектура

Проект состоит из трёх частей.

**Бэкенд** (`backend/`) — REST API на Node.js с фреймворком NestJS. Принимает запросы от мобильного клиента, проверяет данные через class-validator, аутентифицирует через JWT и работает с базой данных PostgreSQL.

**SDK** (`fitness-sdk/`) — отдельная Android-библиотека на Kotlin, которую подключает мобильное приложение. Содержит все репозитории и сервисы: работает с бэкендом через Retrofit и OkHttp, считает шаги через Sensor API, загружает их в фоне через WorkManager.

**Мобильное приложение** (`mobile/`) — Android-приложение на Kotlin. Слой представления построен на Jetpack Compose по паттерну MVVM: экраны подписываются на состояние из ViewModel, ViewModel обращается к SDK через интерфейсы.

## Стек технологий

| Часть | Технологии |
|---|---|
| Бэкенд | Node.js, NestJS, PostgreSQL, JWT, bcrypt |
| SDK | Kotlin, Retrofit, OkHttp, WorkManager, Sensor API |
| Мобильное приложение | Kotlin, Jetpack Compose, ViewModel, StateFlow, Navigation |

## Запуск

### Предварительные требования

**Windows:**
- Docker Desktop 4.0 или выше
- Рекомендуется включить WSL 2 (Windows Subsystem for Linux)

**Linux / macOS:**
- Docker Engine 20.10 или выше
- Docker Compose 2.0 или выше

### Быстрый запуск

**1. Клонировать репозиторий**

```bash
git clone https://github.com/ItzRoXoR/Activity-Monitoring-App.git
```

**2. Убедиться, что Docker запущен**

```bash
docker ps
```

**3. Собрать и запустить бэкенд**

Из директории `backend/`:

```bash
docker-compose up --build
```

При успешном запуске в консоли появится строка `Server running on port 3000`.

**4. Проверить работоспособность**

Откройте в браузере:

- `http://localhost:3000` — основное API
- `http://localhost:3000/api/health` — должен вернуть `200 OK`

## Моки

Моки в проекте не используются. SDK обращается напрямую к бэкенду, бэкенд работает с реальной базой данных PostgreSQL.

## Реализованные сценарии использования

В приложении реализовано два ключевых сценария: «Запуск тренировки» и «Подбор тренировки по параметрам».

### Сценарий 1: Запуск тренировки

Полный цикл взаимодействия с тренировкой — от старта до сохранения результата.

1. В разделе «Тренировки» (иконка гантели в нижнем меню) выберите любую тренировку и нажмите «Старт».
2. Запускается сессия тренировки: отображаются описания упражнений, идёт таймер.
3. Дождитесь окончания тренировки — таймер остановится автоматически.

**Ожидаемый результат:** появляется поздравительное сообщение с количеством сожжённых калорий. В истории сессий появляется новая запись.

### Сценарий 2: Подбор тренировки по параметрам

Выбор подходящей тренировки с помощью фильтров.

**Просмотр списка:**

1. Перейдите в раздел «Тренировки».
2. Отображается список тренировок в виде карточек с названием, типом и длительностью.
3. Нажмите на любую карточку — откроется страница с подробным описанием и кнопкой «Начать тренировку».

**Работа фильтров:**

1. В разделе «Тренировки» нажмите на иконку фильтра.
2. Выберите нужные параметры, например тип «Йога», и примените фильтр.
3. Список обновится — отобразятся только тренировки, соответствующие выбранным критериям.
